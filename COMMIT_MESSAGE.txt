Fix Atlas server-side exception — move charts to a client component (INTERNAL-PORTAL)

The Atlas Overview is a Server Component and was passing the Chart's formatter
functions (tip / yFmt) as props into Chart, which is a Client Component. Next.js
can't pass functions across the server→client boundary, so the page threw a
server-side exception at render time (it built clean because the page is dynamic,
so the build never executed it).

Fix
- New client component AtlasCharts renders both Overview charts; the server page
  passes only the plain data arrays, so no functions cross the boundary.

Verified
- Booted next start and loaded the routes: /atlas -> HTTP 200 (Atlas, Hotspots and
  the growth stats render), /atlas/map -> HTTP 200. No exception.
- tsc --noEmit clean; npm run build green.
