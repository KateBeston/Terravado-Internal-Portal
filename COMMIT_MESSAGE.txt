Add the Regulatory Watch + alert system (INTERNAL-PORTAL)

Fortnightly monitoring of the regulators that touch property, lending, financial
services, real estate, AML, trusts and accounting, with in-portal alerts.

What's new
- Sources registry (src/lib/integrations/regwatch) — seeded bodies (ASIC, APRA,
  ACCC, RBA, AUSTRAC, ATO, TPB, Revenue NSW, SRO Vic, NSW Fair Trading) each with
  a category and an RSS/newsroom feed; overridable via REGWATCH_SOURCES. An
  RSS/Atom parser + collectRegulatoryItems() fetches all, parses, and skips any
  source that's unreachable or unparseable.
- regulatory_alerts table (migration 0023) — shared public-data feed,
  de-duplicated by url; RLS lets any signed-in user read, refresh and acknowledge.
- /regulatory-watch page (nav "Regulatory Watch", gated on integrations): Check
  now, mark-all-read, category filters, the alert list with source links and
  per-row mark-read. A nav badge shows the unread count.
- Fortnightly automation: /api/regwatch + a Vercel Cron (1st & 15th). The cron is
  the one isolated, env-gated service-role path, for PUBLIC data only — inert
  unless CRON_SECRET + the service key are set; the authenticated "Check now" is
  the primary path. It surfaces that something changed and links to it; it does
  not interpret the law.

Honesty / verification
- tsc clean; build green. Booted next start: /regulatory-watch -> 200;
  /api/regwatch -> 401 without the secret.
- The build sandbox can't reach the regulator sites, so the feed fills in once
  deployed (Vercel can); it degrades to an empty feed, never errors.
