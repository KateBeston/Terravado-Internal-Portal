Port Feasibility out of the retired Workspace into a persisted page

The retired Workspace demo held a development-feasibility view that had no
persisted equivalent anywhere in the real portal. This ports it in full and
backs it with a real record so studies survive between sessions and are
tenant-scoped like everything else.

What's new
- /feasibility page (gated on the "stock" capability) — list saved studies,
  select one, create new, delete.
- FeasibilityEditor: the full Workspace view (Scheme / Costs / Funding /
  GST & target panels; KPIs; cost-stack, funding and sensitivity tables),
  now backed by local edit state + a Save action instead of the in-memory
  demo store. The engine's feasibility() does the maths, unchanged.
- feasibilities table (migration 0021) — id, tenant_id, name, data jsonb,
  created_at; RLS tenant-scoped (tenant_id in current_user_tenants()).
- Service CRUD (list/get/add/update/remove) and server actions
  (create/save/delete). The whole feasibility model lives in the data jsonb;
  the shallow case mapper leaves its contents untouched.
- Nav entry under the advisor tools, between Match and Pipeline.

Verification
- tsc --noEmit clean
- npm run verify:engine — 20/20
- npm run build — /feasibility builds (115 kB first load)
