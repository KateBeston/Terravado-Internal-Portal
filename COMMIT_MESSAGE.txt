feat(sharing): external guest deal-sharing — invite onto one deal, view-only, cross-tenant scoped (final layer)

INTERNAL PORTAL.

The final account-model layer: an account can invite an external party onto a
SINGLE deal (a person/client record + its properties, modelling and documents).
The guest sees only that deal — never the host's book.

- deal_shares: host_tenant_id, client_id, invited_email, permission (view |
  collaborate), status (invited | accepted | revoked), token. RLS: the host
  manages its own shares; the invited email can see shares addressed to them.
- Guest read access via SEPARATE *_shared_select policies on contacts,
  properties, report_snapshots, documents and lodgements — SELECT only, scoped
  to shared_client_ids() (accepted shares for the current user by user-id or
  email). Host write access is untouched; guests cannot write.
- accept_deal_share(token) RPC: only the invited email may accept; sets the
  share accepted and binds it to the user.
- Host UI: a Sharing tab on the person record — invite by email, see shares,
  copy the invite link, revoke (cuts access immediately).
- Guest UI: /invite/[token] to accept, /shared to list deals shared with me, and
  /shared/[clientId] a read-only deal view (serviceability snapshot, properties,
  modelling runs). "Shared with me" added to the nav.

Migration 0016 (applied): deal_shares (+RLS, indexes), shared_client_ids() and
accept_deal_share() functions, and the five guest *_shared_select policies.

RLS audit done alongside: every table has RLS enabled; all core data tables are
