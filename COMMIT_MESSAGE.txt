Add Smart Search — build a property record from its address (INTERNAL-PORTAL)

The property-record analog of TGS's Sanctum Smart Search. Enter an address and
Terravado fans out across the integration seams and creates a pre-filled
property record, ready to review on its tabs.

What it populates
- Geocode (lat/lng, place_id) — Google Places when the address is picked from
  autocomplete, else the property-data provider's geocode.
- Suburb data — median, vacancy, growth into the Locality tab.
- Property attributes & value (RP data) — type, beds/baths/cars, land size,
  build year into Physical; unimproved land value into the land-tax field;
  estimated value as the price.
- Title particulars (land registry) — title reference, lot/plan, zoning into
  the Title tab.

Seams & honesty
- New titles seam (src/lib/integrations/titles) — provider interface + stub,
  gated on TITLES_PROVIDER; real broker (GlobalX / InfoTrack / Dye & Durham /
  CITEC) slots in later. Added to the integration registry.
- property-data provider gains propertyAttributes() (stub + CoreLogic
  placeholder).
- smartSearchProperty() orchestrator calls each source independently and
  wrapped, so one unavailable provider degrades to a gap, not a failure. Every
  source reports whether it ran live or on the indicative stub.
- Until CoreLogic/RP data and a titles broker are connected it runs on clearly-
  labelled placeholder data — the UI says so and links to Integrations. No DB
  migration (everything lands in the existing columns + details jsonb).

Verification
