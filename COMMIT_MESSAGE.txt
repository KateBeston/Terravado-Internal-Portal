feat(account): account types + capability gating (layer 1 of the account model)

INTERNAL PORTAL.

First layer of the account model: an account (tenant) now has a TYPE that grants
a set of capabilities, and the portal gates features on those capabilities.

- Account types: Mortgage broker, Investment consultant, Buyers agent, Public /
  end investor. Core (modeller, portfolio, clients, properties, entities) is
  shared; the type adds/removes lenders, finance, lodgement, bank data, deal
  export, integrations and The Business.
- lib/auth/capabilities — the capability matrix + helpers (capabilitiesFor, can,
  labels). Features are gated on CAPABILITIES and the type grants them, so a
  consultant who later adds a broker to the team can be granted broker
  capabilities without rewriting checks.
- Nav is filtered by capability; a new Account page (/account) shows the account
  type, lets an owner/admin change it, and lists what each type enables.
- current_tenant() now returns account_type; getCurrentTenant surfaces it.

Migration 0013 (applied): tenants.account_type (default 'broker', so existing
accounts keep full capability); owner/admin tenants_update RLS policy;
current_tenant() rebuilt to return the type.

Next layers (separate increments): internal role refinements (broker-on-team),
then external guest deal-sharing (cross-tenant, scoped — built last and
carefully). Note: this layer gates the NAV; per-page capability enforcement
lands with the sharing increment.
